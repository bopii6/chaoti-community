## 课眼（这一课存在的意义）

第 4 课学会提示词：老板先把活交代清楚。这一课让学员看见“活还能派到多大”。只靠提示词，Agent 可以完成一件相对清楚的任务；想让它做得更漂亮，就需要给它插上翅膀。

这是一节全景导读，不是配置课。我们先完成，再完美：先知道四样翅膀各解决什么问题，后面再逐个深入。

- **主标题**：让 Agent 员工掌握 72 变，插上翅膀
- **小副标题**：浏览器自动化、MCP、Skill、知识库，先看地图再逐个深入
- **当天产出**：《我的 Agent 能力地图》
- **现场重点**：浏览器自动化真实演示；其他三样先讲位置和价值

## 四样翅膀的地图

| 翅膀 | 它补上的能力 | 一句人话 |
|---|---|---|
| 浏览器自动化 | 打开网页、搜索、读取、填写和整理网页信息 | 让 Agent 自己上网替你干活 |
| MCP | 把外部工具、服务和数据接进 Agent | 给员工接上外部工具插头 |
| Skill | 把一套专业方法封装成可复用的技能 | 让员工多一门稳定专长 |
| 知识库 | 提供你的资料、规则、经验和偏好 | 给员工一个属于你的第二大脑 |

## 先完成，再完美

不要一上来就把四样全部学会。正确顺序是：

1. 先用第三课的提示词，把任务交代到相对清楚；
2. 看结果还缺什么能力；
3. 只补当前任务真正需要的一只翅膀；
4. 跑通一次，再决定是否继续扩展。

提示词是老板的派活能力，翅膀是员工的能力和资料。两者不要混为一谈。

## 浏览器自动化：让 Agent 自己上网干活

很多任务不是写一段话就结束，而是要打开网页、搜索、逐条查看、填写表单或收集数据。浏览器自动化就是把这些网页上的重复动作交给 Agent。

例如课程研究：想找到用户痛点时，不必自己逐个打开 Twitter、小红书或抖音的帖子，可以让 Agent 按关键词、平台和筛选条件去搜集内容，再整理成可分析的材料。

这节课只让大家先建立这个思路，不拆具体浏览器自动化 Skill、内部知识库、安装方法和异常处理。后面会用专门课程讲如何安全地抓取、整理和验证。

### 现场案例：课程网站的内容怎么来的

这个课程网站里有不少内容，就是先让 Agent 通过浏览器自动化去搜集、筛选和整理，再填充到网站的数据结构里。

- Agent 负责打开网页、搜集信息、搬回材料和完成重复整理；
- 老师负责确定研究问题、判断内容是否可信、决定是否采用；
- 最后再由人检查内容和页面结果。

现场会打开一个 Twitter 页面，让 Agent 找到与课程用户痛点相关的内容，再展示从网页材料到课程内容的中间结果。演示重点是工作链路，不是让大家当场学会某个平台的全部操作。

涉及登录、验证码、敏感信息、批量操作和内容发布时，要遵守平台规则，使用低风险测试材料，并保留人工确认点。

## MCP：先知道它是外部工具的插头

MCP 让 Agent 能连接外部工具、服务和数据。可以先把它理解成插头：Agent 本身会思考，但要查询某个系统、操作某个应用或调用某项服务，就需要接上对应的插座。

本课不展开 MCP 的安装、权限和配置。先把它放进地图里，后面的工作流与工具连接课程再深入。

## Skill：为什么需要给员工装技能

很多稍微专业的任务，不能只靠临时几句提示词。Skill 的作用，是把一套稳定的方法、规则、步骤和检查方式封装起来，让 Agent 不必每次从零学习。

后续 Skill 课程会回答三个问题：

1. 一个 Skill 由哪些部分组成，本体通常存在哪里；
2. 为什么 Codex、WorkBuddy 甚至 OpenClaw 都可以使用 Skills；
3. 老师自己常用和已经制作了哪些 Skills。

现在先记住：Skill 是员工可复用的专业能力包，不是收藏夹。只有能在真实任务里稳定复用，才算真正拥有一项技能。

## 知识库：给 Agent 一个第二大脑

知识库主要是给 Agent 用的，不是让你多一个复杂的记笔记负担。

### 使用对象：给员工用

你可以把 Agent 当成公司的员工。员工需要知道公司的业务、项目资料、工作规则和判断方式；这些内容就应该放进它能读取的知识库。

### 内容来源：公司和个人都可以

公司的产品资料、流程文档、客户研究、品牌规则，以及你自己的经验、偏好和长期记录，都可以成为知识库材料。前提是来源清楚、内容可维护，并且不把敏感资料随意交给不该访问的工具。

### 核心作用：让结果更个性化

没有知识库，Agent 更容易给出通用答案；有了知识库，它才能参考你的业务、你的规则和你的经验，生成更个性化、更垂直的内容。

后面的知识库模块会再讲内容怎么整理、怎么存、怎么让 Agent 找得到，以及如何避免资料越来越多却越来越难用。

## 直播演示（35 分钟）

### 演示一：浏览器自动化（20 分钟）

打开 Twitter 页面，给 Agent 一份清楚的提示词：研究某类课程用户痛点，按关键词搜索，筛选相关内容，记录链接、原文摘要和待核验项，再整理成表格。

重点观察：

- 它是否真的打开网页并执行步骤；
- 搜集结果是否保留来源；
- 它遇到登录、验证码或不确定内容时是否停下来；
- 人如何检查结果，再决定是否写进课程。

### 演示二：课程网站案例（5 分钟）

展示本站一条内容从网页搜集、整理到填入网站数据的中间过程，说明浏览器自动化不是“炫技”，而是把重复的信息搬运工作交出去。

### 演示三：三样翅膀的地图（10 分钟）

分别用一句话说明 MCP、Skill、知识库的角色和后续课程，不现场安装或配置：

- MCP：外部工具和数据的连接方式；
- Skill：可复用的专业方法；
- 知识库：给 Agent 使用的长期资料和规则。

## 配套提示词

```text
我现在有一件需要 Agent 完成的事：____。

请先判断它是否需要四样翅膀中的一种：
1. 浏览器自动化：是否需要打开网页、搜索、读取或填写；
2. MCP：是否需要连接外部工具、服务或数据；
3. Skill：是否需要一套稳定、可复用的专业方法；
```

## 验收标准

- 能说出四样翅膀各自解决什么问题；
- 能用浏览器自动化解释一个真实的网页搜集或填写场景；
- 能说明 Skill 是可复用的专业能力包，知识库是给 Agent 用的第二大脑；
- 知道 MCP、Skill、知识库和浏览器自动化的深入课程分别在哪里；
- 不会把“知道存在”误认为“已经配置会用”，能按完成优先的顺序继续学习。

## 常见误区

- 以为听过四个名词就等于已经会配置；
- 四样翅膀一次全装，结果没有一个真实任务跑通；
- 浏览器自动化直接抓取或外发敏感信息，忘了权限、隐私和平台规则；
- 把 Skill 当成收藏品，装了很多却没有稳定方法；
- 把知识库当成给自己看的资料夹，没有整理成 Agent 找得到、用得上的内容；
- 跳过提示词直接追求完美工具，连任务目标和验收都没说清。
