# 第 06 课｜用 CC Switch 切换员工，降低 Agent 使用成本
> 模块一 · ⑥ 成本控制 ｜ 状态：✅ 已确认 ｜ 2026-08-24

## 课眼（这一课存在的意义）
CC Switch 最根本的用途，是切换数字员工，而不只是换一个模型名称。同一个 Codex 入口，可以今天让官方模型处理难活，明天让 DeepSeek、Kimi、GLM 或其他供应商处理日常活。贵模型留给高难度任务，低成本模型承担批量工作，成本控制才有抓手。

- **主标题**：用 CC Switch 切换员工，降低 Agent 使用成本
- **小副标题**：先换供应商，再在 Codex 里选模型；用低风险任务验证真实成本
- **当天产出**：《模型切换记录表》（供应商 / 模型 / 协议 / 路由 / 任务结果 / 成本判断）
- **参考**：CC Switch 官方仓库、中文用户手册与实际使用经验

## 学员痛点
「AI 用起来怎么这么贵？」很多人一直用旗舰模型跑整理、改写、批量初稿等日常任务，等于拿大炮打蚊子；也有人只看单价，忽略了返工、失败和等待时间。本课先学会切换员工，再学会按任务分配成本。

## 核心概念：两种切换不要混淆

### 1. CC Switch 切换供应商 = 换数字员工
从官方 Codex 账号切到 DeepSeek、Kimi、GLM、ModelScope、SiliconFlow 或其他 API 供应商。CC Switch 管理的是供应商配置，主界面选择供应商后点击「启用」，也可以从系统托盘快速切换。

### 2. Codex `/model` 切换模型 = 换当前员工的型号
供应商启用后，在 Codex 中打开模型选择器或输入 `/model`，只能选择当前供应商已经提供、并且已经正确映射的模型。若要从官方员工换成 DeepSeek 员工，必须先回 CC Switch 启用 DeepSeek，再重启 Codex。

## 准备工作：先备份，再准备凭证

1. 从 CC Switch 官方网站或 GitHub Releases 安装，不使用来路不明的安装包。
2. 首次打开可导入已有的 Codex 配置；正式修改前，在设置/数据管理中导出备份。
3. 准备供应商控制台生成的 API Key、官方 Base URL 和可用模型 ID。API Key 只粘贴到 CC Switch 的密码框，不放进提示词、截图、课程文档或公开仓库。
4. 第一次接入只用低风险任务和测试文件夹，不要直接改重要项目、发送消息或执行不可逆操作。

## 完整教程：在 Codex 中接入 DeepSeek

不同版本的按钮文字可能略有变化，但顺序不变：**添加供应商 → 配置协议和模型 → 启用路由 → 激活供应商 → 重启 Codex → 用 `/model` 和测试任务验证**。

### 第 1 步：打开 Codex 供应商面板

1. 打开 CC Switch，进入 Codex 应用页。
2. 点击「添加供应商」或右上角 `+`。
3. 优先选择内置的 DeepSeek 预设。预设会带出常用端点和协议，少填一项就少错一项。
4. 如果没有 DeepSeek 预设，选择「自定义供应商」，再填写名称、API Key、Base URL 和模型 ID。端点以 DeepSeek 官方控制台/文档为准，不要照抄过时截图。

### 第 2 步：填写 DeepSeek 配置

| 字段 | 怎么填 | 检查点 |
| --- | --- | --- |
| 名称 | 例如 `DeepSeek（日常）` | 名称要能看出用途，别只写「测试」 |
| API Key | 粘贴供应商控制台生成的 Key | 只粘贴到密码框，不要发给别人 |
| Base URL | 优先使用预设；自定义时填供应商官方 API 端点 | 不要把完整模型路径误填成 Base URL，除非开启完整 URL 模式 |
| 模型 ID | 填供应商真实模型 ID，或从当前版本列表选择 | 必须与控制台可用名称一致 |
| 协议 | 常见 DeepSeek 接入通常按预设选择 Chat Completions | 协议不匹配会出现 404、格式错误或无响应 |
| 需要本地路由映射 | 非 GPT 模型或 Chat Completions 供应商打开；DeepSeek 预设通常默认打开 | 它负责把 Codex Responses 请求转换给上游 |

### 第 3 步：打开本地路由和 Codex 接管

DeepSeek 这类第三方模型不一定原生提供 Codex 需要的 Responses API。CC Switch 的「需要本地路由映射」会把 Codex 请求转换成上游支持的 Chat Completions，再把结果转换回来。

在 CC Switch 中启动本地路由服务，并在 Codex 应用接管/应用路由中启用 Codex。保存配置后，运行期间不要关闭本地路由；否则 Codex 可能回到旧端点或直接报错。

### 第 4 步：激活供应商，切换数字员工

1. 回到 Codex 供应商列表，找到刚配置的 DeepSeek 卡片。
2. 点击「启用」；也可以从系统托盘的 Codex 子菜单直接点击 DeepSeek。
3. 确认卡片显示为当前供应商。这个动作切换的是 Codex 的后端员工，不是只改了一个模型名称。

### 第 5 步：重启 Codex，再在 Codex 内选模型

1. 完全退出并重新打开 Codex。CC Switch 文档要求重启对应 CLI/工具来应用配置，模型映射也在 Codex 启动时加载。
2. 进入 Codex 后打开模型选择器，或输入 `/model`。
3. 查看当前供应商提供的模型。若 CC Switch 已生成模型映射，列表中会出现你配置的 DeepSeek 模型；选中后，当前会话就会使用它。
4. 只想在同一供应商的多个模型之间切换时，直接用 `/model` 即可；要换成另一家供应商，必须先回 CC Switch 启用对应供应商。

### 第 6 步：用低风险任务验证

不要只看「启用成功」提示。在测试文件夹让 Codex 完成：读取一个 Markdown、列出目录、生成一份小摘要，并说明当前模型和供应商。重点检查四件事：

- 是否正常响应；
- 是否能读文件、调用工具；
- 输出质量是否适合这类日常任务；
- 耗时、失败率和返工次数是否真的更省。

验证失败时，先检查路由服务、API Key、Base URL、协议和模型 ID，不要立刻把问题归因于模型能力。

## 换成其他公司的模型，流程完全一样

换成 Kimi、GLM、MiniMax、ModelScope、SiliconFlow 或其他兼容供应商时，按这条链路操作：

**选择预设或自定义 → 填 API Key → 核对 Base URL、协议和模型 ID → 非 GPT/Chat 协议打开本地路由映射 → 启用路由 → 激活供应商 → 重启 Codex → `/model` 验证。**

不同供应商的模型名、思考参数和工具调用能力可能不同。部分供应商只支持思考开关，不支持 `low / medium / high` 等思考等级；不要看到 Codex 有选项，就默认上游一定支持。工具调用、文件读写和浏览器能力也要单独测试。

## 切回官方 Codex

1. 在 CC Switch 的 Codex 供应商列表中选择官方登录/ChatGPT Codex 预设，或恢复原来的官方供应商。
2. 点击「启用」后重启 Codex。
3. 在 Codex 模型选择器中确认回到官方模型列表，再跑一个小任务验证。
4. 如果使用 CC Switch 的 OAuth 反向代理功能，先阅读账号和服务条款风险；本课不建议把它当作默认入门路径。

## 成本不是只看单价

便宜模型如果频繁返工、不会调用工具或无法完成任务，实际成本可能更高。每次记录四项：**单价、成功率、返工次数、耗时**。日常整理、批量初稿可以先试低成本模型；复杂推理、重要交付和难以验收的任务保留给更稳定的模型。

## 直播演示（40 分钟）

1. 介绍 CC Switch 官方下载、备份和 API Key 安全边界；
2. 在 CC Switch 添加 DeepSeek 供应商；
3. 配置协议、模型 ID，打开本地路由和 Codex 接管；
4. 启用 DeepSeek，重启 Codex，用 `/model` 选择映射模型；
5. 在测试文件夹跑低风险任务，记录响应、工具调用、质量和耗时；
6. 切换到另一家供应商，再切回官方 Codex；
7. 用《模型切换记录表》比较单价与真实完成成本。

## 给 Agent 的提示词模板

```text
我想在 Codex 里使用____供应商的____模型，请按 CC Switch 的方式带我配置：
1. 先判断它是 OpenAI Responses、Chat Completions 还是其他协议；
2. 告诉我应选哪个预设，或需要填写哪些字段：API Key、Base URL、模型 ID；
3. 判断是否需要打开本地路由映射、启动路由服务和启用 Codex 接管；
4. 写出启用供应商、重启 Codex、/model 选择和低风险验证步骤；
5. 任何 API Key、账号登录或付费动作都不要替我执行；
6. 如果模型不支持工具调用或思考等级，请明确提醒我。
```

## 学员练习与交付物

用测试账号或低风险 API Key 完成一次 DeepSeek 接入：记录预设/自定义配置、Base URL、模型 ID、是否启用本地路由、启用前后状态、Codex 重启结果、`/model` 列表和测试任务结果。然后切回官方供应商，填写《模型切换记录表》：

## 验收标准

- 能解释 CC Switch 切换的是供应商，Codex `/model` 切换的是当前供应商内的模型；
- 能完成一次 DeepSeek 供应商添加、启用本地路由、激活、重启和低风险验证；
- 能说出 API Key、Base URL、协议、模型 ID 和模型映射分别是什么；
- 能按同样流程配置另一家公司的预设或自定义供应商；
- 能切回官方 Codex，并知道切换失败先检查哪些配置。

## 常见误区

- 把 CC Switch 的供应商切换和 Codex 的 `/model` 切换混为一谈；
- 切换后不重启 Codex，继续使用旧的配置和模型列表；
- DeepSeek 的协议、Base URL 或模型 ID 填错，出现 404/无响应后却只换模型；
- 忘记打开本地路由或 Codex 接管，第三方 Chat Completions 模型无法正常工作；
- 把 API Key 写进提示词、截图或公开文档；
- 只看单价，不看工具调用、成功率、返工次数和耗时；
- 使用 OAuth 反向代理却没有阅读账号和服务条款风险。
