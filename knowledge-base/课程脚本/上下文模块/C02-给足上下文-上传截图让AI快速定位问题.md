# 2.2｜给足上下文：截图大法，让 AI 快速定位问题
> 模块二 · 上下文 ｜ 状态：✅ 已确认 ｜ 2026-08-24

## 课眼（这一课存在的意义）

截图不是装饰，也不是把整块屏幕随手丢给 AI。它是给数字员工补上下文：参考网站的截图让它看见你的目标和对象，标注后的结果截图让它看见你具体不满意的地方，报错和状态截图让它知道问题发生在哪一步。文字说明目标，截图提供证据，AI 才能更快定位并给出可检查的修改。

- **主标题**：给足上下文：截图大法，让 AI 快速定位问题
- **小副标题**：用参考图说明目标，用标注图指出不满，让 AI 少猜一步
- **当天产出**：三组带说明的截图（参考目标 / 当前不满 / 报错或设备问题）

## 学员痛点

「我说了很多遍，它还是做不对」「我知道不好看，但说不清哪里不好看」「电脑上正常，手机上却乱了」「页面报错了，不知道该截什么」。这些问题通常不是 AI 完全不会，而是它没有看到你看到的上下文。

## 为什么截图能让 AI 少猜一步

你说「这个网站不够专业」，AI 不知道你说的是配色、间距、字体、信息层级还是按钮位置。截图把问题放在同一个画面里，AI 可以先指出它看见的事实，再根据你的目标提出修改。

**截图负责提供证据，文字负责提供判断标准。** 不要只上传图片，也不要只说「高级一点」；把两者放在一起，定位速度和结果质量都会更稳定。

## 场景一：给 AI 一个参考网站，说明你想做成什么

当你要做一个网站，而 Agent 一直做不到你想要的感觉时，截取一个你认可的参考网站：最好包含完整首屏、导航、标题、按钮和主要内容。

告诉 AI：这是参考对象，不是让它复制代码；请分析页面结构、信息密度、字体层级、颜色关系、留白和交互重点，并把这些标准转成你的新网站。截图的作用是给它一个明确的目标和对象，避免它凭空理解「好看」。

- **截图什么**：参考网站首屏，必要时再补一张内容区或移动端截图。
- **旁边写什么**：我喜欢它的____，希望我的网站用于____，不能照搬它的品牌和文案。
- **让 AI 先做什么**：先列出参考图中的结构和视觉规则，等我确认后再开始写页面。

## 场景二：结果不满意，但你说不清哪里不满意

有时候 Agent 已经做出一个页面，你一眼觉得「不对」，但很难用语言说清是哪里不对。这时截取当前结果，用箭头、方框或编号标出具体区域，再用短句描述感受。

例如：1 号区域标题太大，压住了下一段；2 号区域按钮不突出；3 号区域颜色太单一。你不需要先说出设计术语，只要指出位置、现象和你希望的变化，AI 就能把模糊的不满变成可执行修改。

- **截图什么**：当前页面的完整首屏或问题所在区域。
- **怎么标**：一张图尽量只讲一个主题，用 1、2、3 编号，不要画满整张图。
- **旁边写什么**：我不喜欢____，因为____；请先说明你准备怎么改。

## 场景三：网页报错、按钮没反应或流程卡住

当页面出现红色报错、空白、加载不完、按钮点了没反应时，截图能保留「问题发生的现场」。只说「打不开」会丢失关键线索。

最好连续截两张：操作前页面和出错后的页面；如果有浏览器地址栏、错误提示、开发工具 Console 或网络请求状态，也把相关区域截进去，但要先隐藏账号和 Token。

- **截图什么**：地址栏（不含敏感参数）、错误提示、按钮状态、加载状态和必要的 Console 信息。
- **旁边写什么**：我先点击了____，随后出现____；我期待页面____。
- **让 AI 先做什么**：判断是前端样式、权限、网络、接口还是数据问题，不要直接重写整个项目。

## 场景四：对比两个版本，让 AI 找出差异

当你说「上一版更好」时，AI 仍然不知道好在哪里。把旧版和新版并排截图，或者分别上传两张并标明「旧版/新版」，让它逐项对比布局、文字、颜色、间距和功能。

这适合 Agent 改完网站、PPT、海报、表格或文案之后做复盘。你可以要求它只恢复某一项，不要整版回退。

## 场景五：移动端和桌面端显示不一样

网站在电脑上正常，手机上却出现标题换行、按钮被挤出屏幕、表格横向溢出，这类问题只看桌面截图很难定位。分别截取桌面端和手机端同一页面，告诉 AI 目标设备和最不能接受的问题。

截图旁边写清：设备或视口宽度、页面路径、你希望保留的重点，以及哪些内容可以折叠、换行或移动。这样 AI 才会按响应式规则修复，而不是简单缩小字体。

## 场景六：从表格、后台或复杂页面提取信息

当你希望 AI 读取某个网页表格、后台状态或数据面板时，截图可以帮助它先理解列名、筛选条件、时间范围和你要的字段。尤其是页面有多个相似数字时，圈出目标区域能避免它抄错。

截图不能替代原始文件或可复制数据；如果需要精确计算，优先同时提供 CSV、Excel 或文本，截图只用来说明位置和界面含义。

## 场景七：上传前先处理隐私和范围

- 账号、手机号、邮箱、订单号、地址、客户资料、API Key、Cookie、二维码和人脸先打码。
- 只截任务需要的区域，能裁剪就不要上传整张桌面或整个后台。
- 如果截图来自他人网站、付费资料或内部系统，先确认你有权使用和分享。
- 图片太大或文字太小，可以分成「全局图 + 局部图」，并给每张图编号。

## 截图旁边补四句话

1. **背景**：这张图来自哪个页面、哪个版本或哪一步操作。
2. **位置**：问题/参考对象在图中的哪个区域，编号或圈出重点。
3. **现象**：你看到的具体事实，避免只写「不好看」或「不对」。
4. **目标**：希望 AI 判断、修改、提取、复现还是对比；完成后用什么标准验收。

## 先让 AI 定位，再让它动手

上传截图后，第一句不要直接说「帮我改好」。先让 AI 复述它看到了什么、指出问题位置、列出不确定信息和执行计划；你确认定位正确后，再允许它修改文件或操作网页。

截图提供上下文，但不自动授权危险动作。涉及公开发布、删除文件、登录账号、发送数据或付费时，仍然要由老板明确确认。

## 现场演示（30 分钟）

1. 给 Agent 一张参考网站截图，让它拆解目标和结构；
2. 给它一张自己生成但不满意的页面截图，用编号标出标题、按钮和间距问题；
3. 让它先输出定位报告和修改计划，确认后再执行；
4. 补充报错、移动端、表格和版本对比等截图场景。

## 给 Agent 的提示词模板

```text
我上传了____张截图。请把它们当作这次任务的上下文，不要直接修改：
1. 说明每张图来自什么页面/设备/操作步骤；
2. 指出我圈选或编号的区域，并列出截图中能确认的事实；
3. 区分「参考目标」「当前结果」和「报错现场」；
4. 说明你还需要我补充什么；
5. 根据我的目标____，给出修改/提取/复现计划和验收标准；
6. 等我确认定位后再执行。任何账号、密钥、删除、发布或付费动作都先问我。
```

## 学员练习与交付物

准备三组截图：一张你喜欢的参考网站、一张 Agent 当前生成但你不满意的页面、一张真实报错或移动端问题。分别写清背景、位置、现象、目标，让 Agent 先做定位报告，再选择其中一组执行修改并验收。

## 验收标准

- 能判断参考目标、当前结果、报错现场分别该怎么截图；
- 能用标注和「背景 + 位置 + 现象 + 目标」说明不满，而不是只说感觉；
- 能为桌面/手机、表格/后台、版本对比等场景补充合适截图；
- 能在上传前裁剪、编号、打码，并说明截图的权限和隐私边界；
- 能让 Agent 先复述事实、定位问题和列计划，再确认执行。

## 常见误区

- 只上传截图，不说明它是参考目标、当前结果还是报错现场；
- 只说「高级一点」「不好看」，没有标位置、现象和目标；
- 一张图塞太多无关内容，重点区域反而看不清；
- 只截桌面端，不截出现问题的手机端或实际设备；
- 截图里的文字太小、被弹窗遮住，或缺少地址栏/操作步骤；
- 忘记打码账号、手机号、订单信息、Cookie、二维码和 API Key；
- 让 AI 看到截图后就直接改文件或发布，没有先确认它定位是否正确。
