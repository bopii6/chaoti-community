# S2｜Skill 的技能：无痛使用 Skills 技能

## 课眼

找到现成 Skill 不需要先成为程序员。你可以从 Skill 广场、GitHub、内容平台作者分享的链接，或者直接向联网的 Codex 提问开始。先拿现成 Skill 解决真实问题，再让 Agent 按你的材料、口味和验收标准做小幅改造，这就是无痛制作 Skills，做出自己的专属技能。

- **主标题**：Skill 的技能：无痛使用 Skills 技能
- **小副标题**：获取 Skill 技能的四种方式
- **当天产出**：一个试跑过的 Skill + 一份专属 Skill 草稿

## 学员痛点

「GitHub 看着就怕」「安装是不是很麻烦」「看到别人做出好东西，却不知道怎么拿来用」——门槛和信息差让很多人不敢使用 Skill。

## 获取 Skill 的四种方法

| 方法 | 怎么做 | 我的使用建议 |
| --- | --- | --- |
| 1. Skill 广场 | 在正规技能目录按主题搜索、查看说明和安装命令 | 适合入门，先从受众大、文档完整的开始 |
| 2. GitHub 开源 | 看作者仓库、README、SKILL.md、更新记录和许可证 | 适合研究来源和自己改造 |
| 3. 内容平台作者分享 | 在小红书、公众号、视频号等找到作者发布的仓库/下载链接，再拿来试用 | 我经常用，先看作者示例和真实效果 |
| 4. 直接问联网 Agent | 告诉 Codex 你的任务、环境和限制，让它推荐可用 Skill | 我经常用，Agent 能结合当前环境筛选 |

## 方法一：Skill 广场

可以先从 [skills.sh](https://skills.sh/) 或 [LobeHub Agent Skills 市场](https://lobehub.com/skills) 这类面向 Agent Skills 的公开目录开始。它们适合用关键词找技能、看安装方式和了解哪些 Skill 被广泛使用。

Skill 广场是入口，不是质量保证。打开一个 Skill 后仍然要看作者、README、支持的 Agent、权限、依赖、示例和最近更新时间。先选文档完整、用途明确的 Skill，再用低风险任务试跑。

## 方法二：GitHub 开源

很多博主和开发者会把 Skill 放在 GitHub 开源。打开仓库后，先读 `README.md`，再找 `SKILL.md`、`skills` 文件夹、安装脚本和示例。GitHub 的价值是让你看到 Skill 到底由什么规则组成，而不只是看到一个下载按钮。

可以把仓库链接交给 Agent，让它做一次导读：这项技能的目标、步骤、依赖、权限、数据流向和风险分别是什么。确认后再安装，不要因为 Star 多就跳过检查。

可以直接从这些中文社区常被分享的仓库开始：
- 宝玉：[JimLiu/baoyu-skills](https://github.com/JimLiu/baoyu-skills)（适用于 Claude Code、Codex 等）；
- 卡兹克：[KKKKhazix/human-writing](https://github.com/KKKKhazix/human-writing)（活人感写作）；
- 烁皓：[eternityspring/shuohao-skills](https://github.com/eternityspring/shuohao-skills)（novel-* 等技能）。

## 方法三：从小红书、公众号、视频号找到作者分享的 Skill

这是我经常使用的方法。你在小红书、公众号或视频号里看到别人做出一个很有用的东西，作者通常会在文章、评论区、置顶内容或个人主页放 GitHub 仓库、下载链接或安装说明。找到链接后，不要只收藏内容，让 Agent 帮你下载或安装到自己的环境，再直接试用。

流程是：看到真实效果 → 找到原始链接 → 让 Agent 读懂 Skill → 让 Agent 下载/安装到自己的环境 → 试跑 → 记录哪些地方适合、哪些地方需要改。作者的案例是参考，不代表它一定适合你的设备、工具和工作方式。

## 方法四：直接让联网的 Codex 推荐 Skill

这也是我经常使用的方法。因为 Codex 可以联网，而且知道你当前的项目、文件结构、操作系统和已安装能力，你可以直接问它：「我想完成这件事，当前环境适合用什么 Skill？」

让 Agent 推荐时，不要只问「有什么好 Skill」，要把任务、已有工具、预算、隐私边界和最终交付说清楚。让它给出 2—3 个候选，并比较适用场景、依赖、权限、成本和风险，再写一个最小试跑任务。

## 无痛制作：先用现成 Skill，再做专属版本

「制作 Skills」不等于从空白文件开始写一大套规则。更轻松的路径是：找到一个接近的现成 Skill → 让 Agent 解释它的规则 → 用你的材料和样例试跑 → 把你的偏好、边界、自检标准补进去 → 保存成自己的专属 Skill。

专属 Skill 至少要有三件东西：规则（怎么做、不许怎么做）、示例（什么叫好）、自检（交付前检查什么）。这样你不是把 Skill 当收藏品，而是把别人的方法真正变成自己的工作能力。

## 一句话安装与验证

如果 Skill 提供了安装命令，例如 `npx skills add`，让 Agent 先解释命令会下载什么、写入哪里、需要什么权限，再由你确认后执行。装完不要凭「安装成功」判断可用，要立刻跑一个真实但低风险的小任务。

验证四件事：Agent 是否识别到 Skill、是否按规则执行、结果是否达到示例标准、有没有修改或上传超出预期的文件。

## 现场演示（35 分钟）

1. 从 skills.sh 或 LobeHub 找一个 Skill；
2. 从 GitHub 打开一个开源 Skill；
3. 从小红书/公众号作者分享的链接找到一个实际可用的 Skill；
4. 让联网 Codex 根据当前环境推荐候选；
5. 选一个试跑，再把规则、示例和验收改成自己的专属版本。

## 给 Agent 的提示词模板

```text
我想完成的任务是：____。我的设备/系统/Agent/已有工具是：____。
请按四种来源帮我找 Skill：
1. Skill 广场：给出正规目录链接和候选；
2. GitHub 开源：给出仓库、作者、README/SKILL.md 和许可证；
3. 内容平台作者分享：如果我提供了小红书/公众号/视频号链接，请找到原始仓库或下载入口，并说明来源；
4. 直接推荐：结合我当前环境筛选 2—3 个能跑起来的候选。
对每个候选说明：解决什么问题、安装命令、依赖、权限、成本、风险和最小试跑任务。
先不要安装；等我确认后，再把最接近的一个改成我的专属 Skill。
```

## 学员练习与交付物

为一个真实任务分别走四种寻找方式，至少拿到 2 个候选 Skill。选 1 个在测试目录跑通，记录来源、安装方式、权限、依赖、输出效果和风险；最后让 Agent 加入你的规则、示例和自检，保存成一个专属 Skill。

## 验收标准

- 能说出四种获取 Skill 的方法，并知道第 3、4 种更贴近自己的实际工作；
- 能提供 skills.sh、LobeHub 等 Skill 广场链接，并知道如何阅读 GitHub 开源仓库；
- 能从小红书、公众号、视频号找到作者分享的原始链接并拿来试用；
- 能让联网 Codex 结合当前环境推荐候选 Skill，而不是只看热门榜单；
- 能完成一次低风险安装和验证，并把现成 Skill 改成包含规则、示例、自检的专属版本。

## 常见误区

- 只记住一个安装命令，不知道 Skill 从哪里来、是否可信；
- 看到 Skill 广场或 GitHub 的热门数字就直接安装，跳过 README、权限、许可证和依赖检查；
- 只收藏小红书/公众号里的链接，没有拿到自己的 Agent 里试跑；
- 让 Agent 推荐时只问「有什么好 Skill」，不给当前环境、任务和限制；
- 把现成 Skill 原样当成自己的专属技能，没有补个人材料、样例、边界和验收；
- 装了一堆不用，增加上下文开销，反而让 Agent 选择困难。

## 配套模板

《Skill 试用记录》：来源 / 仓库或链接 / 解决什么问题 / 安装方式 / 依赖和权限 / 跑通了什么 / 输出效果 / 风险 / 是否改成专属版本。
