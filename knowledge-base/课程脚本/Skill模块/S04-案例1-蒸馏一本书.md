# 2.6｜Skill进阶：把一本书蒸馏成 Skill
> Skill 模块（七十二变之一变：让 Agent 获得专长）｜ 状态：待确认 ｜ 2026-08-24

## 课眼
案例课：把一本方法论强的书蒸馏成可复用的 Skill——以后做同类事，AI 按书里的方法干，而不是每次只复述一遍书里的观点。

- **主标题**：Skill进阶：把一本书蒸馏成 Skill
- **小副标题**：不用读完，让 AI 把书里的方法论变成可执行的技能
- **当天产出**：一个「读书 Skill」（书的方法论压缩版）

## 学员痛点
「书买了读不完」「读了记不住」——书里的方法用不上。

## 核心内容
1. **先判断这本书值不值得做成 Skill**：优先选有明确流程、判断标准和反例的方法论书；纯故事、观点合集和需要大量作者个人经历的书，不适合直接蒸馏。
2. **先做知识地图，不要一上来让 AI 总结全书**：输入目录、章节摘要和关键段落，让 AI 先整理“概念 → 原则 → 步骤 → 适用条件 → 反例”的关系。
3. **把观点翻译成动作规则**：每条方法都要回答“什么时候用、先做什么、看到什么信号要停、什么结果算完成”。“要写得有逻辑”不算规则；“先列出结论，再补三条证据，缺证据就标记待核实”才算规则。
4. **把 Skill 写成三件套**：规则文件（方法和边界）+ 示例库（正确/错误各一例）+ 验收清单（可逐项检查）。书名和作者只作为来源，不把整本书原文复制进 Skill。
5. **用两个不同任务验证迁移性**：一个任务贴近书中案例，一个任务换领域；如果只有原案例有效，说明做成了读书笔记，还没有做成 Skill。

## 蒸馏流程
1. 选一本书，明确“我想借它解决什么真实问题”。
2. 准备合法可用的材料：目录、自己的读书笔记、公开试读内容或自己购买后整理的摘录。
3. 让 Agent 输出第一版知识地图，并要求区分原文事实、作者推论和 Agent 的归纳。
4. 逐条改写成“触发条件—操作步骤—判断分支—输出格式—验收标准”。
5. 补一组正例、反例和边界案例，保存为 `SKILL.md` 及 `examples/`。
6. 用新对话调用 Skill，记录哪里遵守了方法、哪里还是泛泛而谈，再迭代一轮。

## 可直接使用的提问模板
```text
我想把《书名》中的方法用于解决：【真实任务】。
我提供的材料包括：【目录/我的笔记/合法摘录】。

请先不要写总结，先建立一张方法地图：
1. 作者要解决的问题；
2. 核心原则；
3. 可执行步骤；
4. 适用条件和不适用条件；
5. 常见误用和反例。

然后把它改写成一个 Skill 草稿。每条规则必须写清：触发条件、动作、判断分支、输出格式、验收标准。
不能确认的内容标记“待核实”，不要补写书中没有的观点。
最后给出 2 个正例、2 个反例，以及一个换领域测试任务。
```

## 直播演示
现场用一本写作或笔记类方法论书：先让 Agent 画方法地图，再把其中一章改成 Skill，最后分别完成“整理一篇材料”和“处理一个新主题”两个任务，展示“读书笔记”和“可调用技能”的差别。

## 学员练习
选一本你想用的书，蒸馏成 Skill 并跑通一个任务。

## 验收标准
能说清“方法地图—规则—示例—验收”的链路；得到一个 `SKILL.md`；换一个新任务仍能按书的方法工作；能指出至少一条不适用边界。

## 常见误区
选叙事型书；把全书压成一篇摘要；只写“请按照某某书的方法”；没有触发条件和验收标准；把版权材料整段复制进 Skill；只用书中原案例测试一次。

## 配套模板
蒸馏卡：书名与来源 / 要解决的问题 / 核心原则 / 方法地图 / 触发条件 / 步骤 / 判断分支 / 正反例 / 禁止事项 / 验收任务。
