# 3.3｜知识库进阶：让外部素材自动流进来
> 知识库模块（七十二变之一变：让 Agent 懂你）｜ 状态：待确认 ｜ 2026-08-24

## 课眼
3.4 是让 Agent 读知识库，3.3 是让外部素材进入知识库。知识库不是无差别的资料仓库：真正值得保存的，是和个人或公司业务相关、以后能反复调用的上下文。吸收作者的维护心法“在结论刚产生时落盘”，再加一层更稳的流程：先进入收件箱，筛选和加工后再进入正式目录，并标记来源、状态和复核时间。

- **主标题**：知识库进阶：让外部素材自动流进来
- **小副标题**：从收件箱到正式知识：筛选、落盘、复核、归档
- **当天产出**：一条带来源、判断、状态和复核时间的素材记录

## 学员痛点
「好文章、好灵感、好结论散在聊天和网页里」——手动复制粘贴太慢，什么都收藏又会把知识库变成垃圾场。

## 必要性：用七类素材丰富你的第二大脑
学习这节小课，不是为了再学一个“自动搬运”技巧，而是为了让你的第二大脑持续获得真实、可复用的内容。关键问题是：怎样让外部素材高效、优雅地进入知识库，既保留当时的上下文，又方便 Agent 以后调用。

可以进入知识库的素材主要有七类：

1. **与 AI 的互动记录**：你和 Agent、Codex、WorkBuddy 聊天时产生的好结论、好方法、提示词和解决方案，趁上下文还在时直接落盘；
2. **优质的自媒体内容**：筛选你认可的公众号、视频号、抖音、小红书或其他创作者内容，保存来源、观点和可借鉴之处；
3. **读书笔记**：在微信读书等平台产生的摘录、批注和读后判断，整理成自己的方法和行动，而不是只保存原文；
4. **客户聊天记录**：把经过授权、脱敏的聊天截图交给 Agent，转成可检索的文字记录，保留客户原话、需求、异议和下一步；
5. **个人笔记与录音**：日常手写或电子笔记、语音备忘和会议录音，转写后留下当时的判断、场景和待办；
6. **个人自媒体账号内容**：自己的公众号、小红书、抖音等账号里的文章、脚本、数据和复盘，是最贴近个人风格的长期资料；
7. **个人习惯与偏好**：工作、健身、阅读、学习 AI 的习惯，以及表达偏好、决策标准和禁用项，让 Agent 越来越像你的数字员工。

这些素材不需要一次性全部整理。先从最常出现、最能影响你决策或产出的两三类开始，统一进入收件箱，再由你确认是否成为正式知识。

## 核心内容
1. 先筛选：与个人/公司业务相关、可复用、会影响决策或产出的内容，才值得进库；
2. 再个性化：补充业务关系、适用场景、自己的判断、改法和限制；
3. 先入收件箱：不把未经审核的材料直接混进正式知识；
4. 统一格式：标题、来源、日期、摘要、我的判断/用途、标签、原始链接、状态、复核时间；
5. 事实与观点分开，冲突时保留来源并报告冲突，不让 Agent 默默替你拍板；
6. 保持边界：不直接改原始资料，不让 Agent 擅自删除文件；
7. 本节完成“筛选—写入—验收”，下一模块再讲如何调用知识库写公众号。

作者的维护心法可以概括为：结论刚产生时就落盘，保存“判断 + 当时处境”，不要等上下文丢失后再整理。我们的课程再补一个原则：读可以广，写要窄，正式目录只接受经过确认的内容。

数字生命卡兹克关于知识库的提醒可以概括为：知识库不是越大越好，而是要成为 Agent 能调用的、与你真实工作相关的上下文。无差别收集制造噪音，持续筛选和沉淀才有价值。

## 直播演示
现场选一段 AI 聊天内容和一个公开网页/浏览器采集结果：先写入 `00_收件箱`，让 Agent 判断是否值得入库，再整理为 Markdown 写入正式目录，最后打开文件检查来源、个人判断、状态、复核时间和实际路径。

## 学员练习
选一段聊天记录，或一个公开网页/浏览器采集结果，交给 Agent 判断并写入收件箱；确认生成 Markdown 文件后，再决定是否晋升到正式目录，并检查来源、个人判断/用途、状态、复核时间和文件路径。

## 验收标准
能判断一条素材是否值得入库；至少通过聊天内容或浏览器采集中的一种方式成功写入 Vault；文件先进入收件箱，再由人确认是否进入正式目录；文件有来源、个人/业务上下文、状态和复核时间；能确认实际 Markdown 路径，并说清 3.3 是存、3.4 是读。

## 常见误区
什么都往里塞（知识库变垃圾场）；只复制原文不加业务上下文；手动复制粘贴导致流程中断；不保留来源；没有检查写入位置；把未验证材料直接放进正式目录；没有复核和归档；让 Agent 直接修改原始资料或删除文件。

## 配套模板

```text
请帮我把下面这份外部素材整理后写入我的 Obsidian 知识库。
1. 先判断是否值得入库：是否与我的个人/公司业务相关、是否可复用；不值得就说明原因，不要写入。
2. 不要直接修改或删除原始材料。
3. 值得入库时，提炼标题、核心内容和可复用结论，并补充：与我的业务的关系、我的判断/用途、适用场景与限制。
4. 保留来源、原始链接、日期和标签；把事实与我的观点分开。
5. 先写入 Vault 的 `00_收件箱`，不要直接进入正式目录；如果我明确确认，再移动到合适文件夹。
6. 补充状态（有效/待验证/已过期）和建议复核时间。
7. 完成后返回：是否入库、文件路径、写入摘要、来源、状态和下一步。

素材来源：____
原始链接：____
素材内容：____
```
