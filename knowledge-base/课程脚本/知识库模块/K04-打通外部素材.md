# 2.13｜知识库进阶：让外部素材自动流进来
> 知识库模块（七十二变之一变：让 Agent 懂你）｜ 状态：待确认 ｜ 2026-08-24

## 课眼
2.12 是让 Agent 读知识库，2.13 是让 Agent 把外部素材存进去。但知识库不是无差别的资料仓库：真正值得保存的，是和个人或公司业务相关、以后能反复调用的上下文。筛选、加工、写入，才是把外部信息变成自己的资产。

- **主标题**：知识库进阶：让外部素材自动流进来
- **小副标题**：让 Agent 替你筛选、整理、写入，而不是手动复制粘贴
- **当天产出**：一条带来源、带个人判断、真正写入 Vault 的素材记录

## 学员痛点
「好文章、好灵感、好结论散在聊天和网页里」——手动复制粘贴太慢，什么都收藏又会把知识库变成垃圾场。

## 核心内容
1. 先筛选：与个人/公司业务相关、可复用、会影响决策或产出的内容，才值得进库；\n2. 再个性化：补充业务关系、适用场景、自己的判断、改法和限制；\n3. 两种方式：保存有价值的聊天内容；通过 2.14 的浏览器自动化采集外部内容后入库；\n4. 统一格式：标题、来源、日期、摘要、我的判断/用途、标签、原始链接；\n5. 保持边界：不直接改原始资料，不让 Agent 擅自删除文件；\n6. 本节只完成“存进去”，下一模块再讲如何调用知识库写公众号。\n\n数字生命卡兹克关于知识库的提醒可以概括为：知识库不是越大越好，而是要成为 Agent 能调用的、与你真实工作相关的上下文。无差别收集制造噪音，持续筛选和沉淀才有价值。

## 直播演示
现场选一段 AI 聊天内容和一个公开网页/浏览器采集结果：先让 Agent 判断是否值得入库，再整理为 Markdown 写入 Vault，最后打开文件检查来源、个人判断和实际路径。

## 学员练习
选一段聊天记录，或一个公开网页/浏览器采集结果，交给 Agent 判断并入库；确认生成 Markdown 文件，并检查来源、个人判断/用途和文件路径。

## 验收标准
能判断一条素材是否值得入库；至少通过聊天内容或浏览器采集中的一种方式成功写入 Vault；文件有来源和个人/业务上下文；能确认实际 Markdown 路径，并说清 2.12 是读、2.13 是存。

## 常见误区
什么都往里塞（知识库变垃圾场）；只复制原文不加业务上下文；手动复制粘贴导致流程中断；不保留来源；没有检查写入位置；让 Agent 直接修改原始资料或删除文件。

## 配套模板

```text
请帮我把下面这份外部素材整理后写入我的 Obsidian 知识库。
1. 先判断是否值得入库：是否与我的个人/公司业务相关、是否可复用；不值得就说明原因，不要写入。
2. 不要直接修改或删除原始材料。
3. 值得入库时，提炼标题、核心内容和可复用结论，并补充：与我的业务的关系、我的判断/用途、适用场景与限制。
4. 保留来源、原始链接、日期和标签；把事实与我的观点分开。
5. 写入 Vault：D:\我的知识库，归入合适文件夹。
6. 完成后返回：是否入库、文件路径、写入摘要。

素材来源：____
原始链接：____
素材内容：____
```
