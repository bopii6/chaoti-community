# 3.4｜知识库进阶：让 Agent 读你的知识库
> 知识库模块（七十二变之一变：让 Agent 懂你）｜ 状态：待确认 ｜ 2026-08-24

## 课眼
完成两件事：先让 Agent 看见本地文件，再让它知道“去哪找、什么能信、应该放回哪里”。吸收作者的“三层导航”做法：根目录的 Agent 导航文件、给人看的总览 README、每个目录自己的 README；目录是地图，README 是路牌，Agent 先读规则再检索正文。

- **主标题**：知识库进阶：让 Agent 读你的知识库
- **小副标题**：目录是地图，README 是路牌，Agent 先读规则再找文件
- **当天产出**：一个 Agent 能读的最小知识库（内容层 + 导航层 + 连通测试）

## 学员痛点
「我已经建了知识库，但 Agent 到底能不能读到？」——先不要急着整理，先把本地文件和 Agent 的代码工具连通。

## 核心内容
1. 从 Obsidian 官方网站下载并安装：https://obsidian.md/download；
2. 创建一个本地 Vault，并按“收件箱 / 日常 / 项目 / 长期知识 / 归档 / 私密 / 附件”建最小目录；
3. 在根目录写 `AGENTS.md` 和 `README.md`，在一个子目录写 `README.md`；
4. 找到 Vault 的真实本地路径，在 Codex 等 Agent 的代码工具中运行 PowerShell 连通测试；
5. 让 Agent 先读导航文件，再回答一个“去哪找”的问题，并返回实际文件路径；
6. 今天只做读取和小范围写入，不做批量修改、删除或复杂搜索系统。

## 直播演示
打开 Obsidian 官方下载页，创建本地 Vault、导航文件和「连通测试」笔记；在 Codex 的代码工具中运行下面的 PowerShell 命令，把路径替换成自己的 Vault 路径：

```powershell
$vault = 'D:\我的知识库'; $files = Get-ChildItem -LiteralPath $vault -Recurse -File -Filter *.md; Write-Output "发现 $($files.Count) 个 Markdown 文件"; $files | Select-Object -First 10 -ExpandProperty FullName
```

看到文件名后，让 Agent 读取 `AGENTS.md`、根目录 `README.md` 和一个子目录 README，再完成一次“找文件 + 返回路径”的测试。

## 导航三件套示例

根目录 `AGENTS.md` 只写 Agent 必须遵守的规则：

```text
先读本文件，再读相关目录 README。
日记按年份进入 10_日常记录；涉及财富数字时，唯一事实源是 40_决策与原则/财富数据.md。
新结论默认写入 00_收件箱；只有用户明确确认后才移动到正式目录。
发现冲突时列出冲突文件和依据，不要自行覆盖。
不得读取或提交 _private 中的内容。
```

根目录 `README.md` 写给人看的总览：这个库服务什么任务、有哪些主要目录、哪些内容是正式知识、从哪里开始找。

子目录 `README.md` 写局部规则：这个目录放什么、不放什么、文件如何命名、和相邻目录的边界，以及是否允许进入 Git。三份说明各司其职，避免把同一条规则复制三遍。

## 学员练习
下载 Obsidian，创建本地 Vault、导航文件和「连通测试」笔记，在 Agent 的代码工具中替换真实路径并运行测试命令；再完成一次“找文件 + 返回路径”的测试，保存结果截图。

## 验收标准
能从官网安装 Obsidian；能创建本地 Vault 并找到真实路径；能写出根目录/子目录导航文件；能运行连通测试命令；Agent 能列出并定位至少一个 `.md` 文件；知道今天只做小范围读取和验证。

## 常见误区
从不明网站下载；拿示例路径直接运行；路径含空格却不加引号；第一次测试就使用客户资料、密码或 Token；一上来让 Agent 改名、移动或删除文件；把「能列出文件」误认为已经完成知识库结构化；没有唯一事实源；让 Agent 在没有明确指令时大范围写入。
