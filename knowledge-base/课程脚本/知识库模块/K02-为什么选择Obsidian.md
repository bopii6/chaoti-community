# 2.11｜知识库进阶：为什么我们要选择 Obsidian？
> 知识库模块（七十二变之一变：让 Agent 懂你）｜ 状态：待确认 ｜ 2026-08-24

## 课眼
让学员先看清一个顺序：AI Native 的主角是 Agent，知识库只是 Agent 要调用的工作底座。我们选择 Obsidian，不是因为它是唯一正确的笔记软件，而是因为它把资料保存在本地普通文件夹里，用 Markdown 表达，方便 Agent 读取、检索、处理和写回，也不把长期资产押在某个云端平台是否提供 API 上。Obsidian 本质上只是编辑器，真正的底座是自己拥有的文件；选工具不是追功能，而是让 Agent 用得舒服、资料能长期迁移。

- **主标题**：知识库进阶：为什么我们要选择 Obsidian？
- **小副标题**：Obsidian 只是编辑器，本地 Markdown 才是底座
- **当天产出**：一个本地 Vault + 安全的最小目录 + 备份方案

## 学员痛点
「知识库工具那么多，选哪个？」——担心资料被平台锁定、隐私不清楚，也担心 Agent 以后读不了自己的资料。更关键的是：如果资料只存在别人的服务器里，而平台不提供 API 或限制调用，Agent 就无法稳定使用；这不符合围绕 Agent 组织工作的 AI Native 习惯。

## 必要性：先让 Agent 有一块能随时调用的底座
AI 时代真正的主角不是某个云端知识库，而是 Agent。我们建立知识库、整理目录、写 Markdown，最终都应该围绕一个问题：Agent 能不能找到、读懂并调用这些资料，替我们完成真实工作。

云端知识库的资料存在平台服务器里。只要平台没有开放 API、改变权限或停止服务，外部 Agent 就可能无法调用；即使能导出，也可能遇到格式、附件和权限的迁移成本。把关键资料放在本地普通文件夹中，Agent 可以直接读取文件、检索内容、按规则写回结果，工具换了也不必重新把资料交给平台。

所以选择 Obsidian 的理由不是“它比所有云端工具都强”，而是它提供了一个成熟、热门、插件丰富的本地 Markdown 入口。先把资料放在自己手里，再让 Agent 围绕这份资料工作；同步、备份、协作和权限可以按需要补上，但不能让云端平台成为 Agent 能不能调用你的资料的前提。

## 核心内容
1. 选择 Obsidian 的第一理由：本地文件，资料归自己所有，Agent 不必依赖某个云端平台是否允许调用；
2. 第二理由：Markdown 和普通文件夹天然适合 Agent 读取、检索、批量处理和迁移；
3. 第三理由：链接、标签和元数据可以给机器提供额外的上下文结构；
4. 第四理由：离线优先、可迁移、可渐进扩展，不被一个平台或 Agent 锁住；
5. 文件夹要服务于检索，不必一开始重构全部资料；已有云库先导出、转换、修复附件路径，再逐步迁移。迁移时重点检查文件名 hash、图片相对路径和中文编码；
6. 边界：本地不等于绝对安全，必须有加密、同步和备份；团队协作、权限审批、数据库和看板场景，也不一定适合用 Obsidian 代替所有工具。

## 直播演示
现场建立一个本地 Vault，建「00_收件箱 / 10_日常记录 / 20_项目 / 30_长期知识 / 90_归档 / _private / _assets」等最小目录，写一篇带来源和日期的 Markdown 笔记，让 Agent 找到并使用它，再用其他编辑器打开同一文件。说明“原始—整理—产出”是内容处理流程，不是必须照抄的固定目录。

## 学员练习
安装 Obsidian，建一个本地 Vault 和最小目录，写一篇带来源、日期、用途、状态和复核时间的 Markdown 笔记；完成一次读取任务，并写下同步/备份边界。

## 验收标准
能说出 Obsidian 的本地归属、隐私、Markdown、可迁移和 Agent 友好等优势；建好一个最小 Vault；能说明导出迁移、备份、同步、插件和团队协作的边界。

## 常见误区
把本地文件误认为绝对安全；一上来装一堆插件；把 Obsidian 当网盘存视频和所有大附件；只看关系图谱不整理正文；没有备份和同步方案；把私密文件和可提交文件混在一起；误以为 Markdown 自动等于结构化。

## 配套模板
Obsidian 建库清单：本地 Vault / 最小目录 / Markdown 模板 / 标题来源日期 / 状态和复核时间 / Agent 读取测试 / 备份方案 / 同步边界 / 私密目录 / 插件需求。
