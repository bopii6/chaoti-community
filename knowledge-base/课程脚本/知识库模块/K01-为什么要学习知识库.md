# 2.10｜知识库进阶：为什么要学习知识库？
> 知识库模块（七十二变之一变：让 Agent 懂你）｜ 状态：待确认 ｜ 2026-08-24

## 课眼
让学员理解：知识库的价值是被 Agent 激活的。没有 AI 时，它更像笔记；有了能读库、找资料、按规则办事的数字员工，它才变成业务上下文和 AI 的工作底座。作者的关键判断是：Agent 的原生接口是读文件、搜文件、写文件，因此本地优先值得作为默认起点；但本地优先不等于只保留一份本地副本。

- **主标题**：知识库进阶：为什么要学习知识库？
- **小副标题**：从收藏夹到 Agent 的工作底座：先定义要解决的任务
- **当天产出**：一页「我的知识库规划」+ 5 个检索测试问题

## 学员痛点
「AI 不是什么都知道吗，我还要存什么？」——没有自己的业务资料，AI 给出的答案听起来正确，却总是空泛，不能直接用于你的工作。

## 核心内容
1. 没有 AI 时，知识库更像笔记或知识清单，人仍然要自己翻阅；
2. Agent 让知识库从“存资料”变成“给数字员工提供业务上下文”，核心动作是找到、读懂、写回；
3. 本地 Markdown 和普通文件夹天然适合 Agent 调用，但云端协作、同步和权限场景仍有价值；
4. 知识库不是越大越好，要围绕真实任务沉淀高频、稳定、可复用的资料，避免“什么都存”制造噪音；
5. 每条重要知识都要有来源、日期、适用范围、状态和必要的复核时间；
6. 先用 5 个真实问题验收“找得准不准”，再决定是否需要更复杂的搜索系统。

## 直播演示
对比演示：A 不给资料让 Agent 写业务周报；B 给一周工作记录、业务规则和历史案例，让 Agent 基于资料写同一份周报，比较通用答案和业务答案的差别。

## 学员练习
选一个每周都会遇到的任务，收集 3—5 份资料，写一页《我的知识库规划》：服务什么任务、存什么、哪些不存、Agent 要产出什么、资料多久复核；再写 5 个检索问题，让 Agent 基于这套资料完成一次任务。

## 验收标准
能解释没有 Agent 和有 Agent 时知识库价值的区别；能区分通用知识、个人上下文和业务上下文；能围绕一个真实任务设计最小知识库；能说出资料的来源、时效、复核和检索验收方法。

## 常见误区
把知识库当成收藏夹；以为 AI 什么都知道；只存外部文章、不存自己的案例和规则；资料没有来源、日期和目录；把过时内容和新规则混在一起；把“本地”误解成“绝对安全”；一开始就追求大而全，没有先用真实任务验证。

## 配套模板
知识库规划卡：服务的真实任务 / Agent 最终产出 / 现有资料 / 通用知识 / 个人上下文 / 业务上下文 / 哪些不存 / 来源与日期 / 复核周期 / 第一轮验证任务 / 5 个检索测试问题。
