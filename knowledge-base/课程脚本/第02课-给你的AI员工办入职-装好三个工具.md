# 第 02 课｜给你的 AI 员工办入职：装好三个工具
> 模块一 · ② 拥有工具 ｜ 状态：✅ 已确认 ｜ 2026-08-24

## 课眼（这一课存在的意义）

第 1 课让学员看见 AI 能干活；这一课让学员真正开始挑员工。重点不是把热门工具全装一遍，而是理解：**AI 工具几乎决定任务完成度，员工越聪明，你越不用事无巨细地盯着它。**

- **主标题**：给你的 AI 员工办入职
- **小副标题**：先挑优秀员工：用 Codex、WorkBuddy、Trae 各跑通一件擅长的事
- **当天产出**：《AI 员工入职卡》+《Codex / WorkBuddy 对比表》+ 三次跑通记录
- **主线**：Codex + WorkBuddy
- **横向试用**：Trae
- **升级伏笔**：Codex 接入其他 AI 工具，放到 1.6

## 第一条经验：先挑优秀员工

真正值得长期培养的员工，不只是会聊天，而是能理解上下文、拆解任务、操作文件和工具、遇到错误会修、交付前会自检。

工具能力上限越高，你就越少需要把每个细节交代一遍。选工具时，优先看它能不能把一件真实任务从输入推进到可检查的交付，再看界面、价格和安装难度。

## 第二条经验：一定要自己试用

每个人的任务、设备、网络和习惯都不同。课程不会把某个工具包装成唯一答案，WorkBuddy 和 Trae 都要亲自用过，才知道谁适合你的工作。

试用不要只问“它会不会回答”，而要给它一件有输入、有步骤、有结果的真实小事。连续跑三次，记录：

- 是否能读懂材料；
- 是否能调用工具完成步骤；
- 出错后能不能继续修；
- 最终结果是否能直接交付；
- 你需要补充多少说明、返工多少次。

## Codex 和 WorkBuddy 怎么选

| 任务场景 | 优先用谁 | 为什么 / 怎么判断 |
|---|---|---|
| 生成比较好看、比较专业的图片 | Codex | 本课实测优先用 Codex，尤其是需要结合参考资料、视觉要求和多轮修改的任务；最后人工检查构图、文字和事实。 |
| 调用浏览器自动化 | Codex | 需要打开网页、读取页面、抓取信息或执行网页操作时，优先用 Codex；涉及登录、发布、删除等动作必须人工确认。 |
| 跨文件、跨工具的复杂任务 | Codex | 适合读项目、改文件、运行命令、验证结果，再继续迭代；任务链越长，越能体现 Agent 的执行能力。 |
| 周报、表格、资料整理等办公任务 | WorkBuddy | WorkBuddy 的定位是办公工作台，适合把文字、表格和日常材料整理成可直接使用的结果。 |
| 外部调研、竞品分析、PPT 初稿 | WorkBuddy | 官方能力覆盖网络调研、信息分析和演示文稿生成，适合先把资料搜集和结构化交付跑通。 |
| 多专家协作的办公流程 | WorkBuddy | 需要运营、设计、数据等角色并行时，可先用 WorkBuddy 的专家团；先看结果是否可核对，再扩大任务范围。 |

上表中的“优先”是课程实测和产品定位的起点，不是永远不变的排名。模型、版本和任务变化后，要重新试用。

## 三个工具怎么放

| 工具 | 官方定位 | 本课怎么用 |
|---|---|---|
| Codex | 跨文件执行、浏览器/编辑器/终端协作、Skills、多智能体和后台任务 | 主力员工：做图片、浏览器自动化、网页/代码和复杂跨步骤任务 |
| WorkBuddy | 多专家办公工作台，覆盖调研、PPT、业务数据和多渠道接入 | 办公员工：做资料整理、表格、报告、调研和办公流程 |
| Trae | TraeWork 是 AI 工作助手，TraeCode 是 AI 编程工程师 | 横向试用：各跑一次同类任务，记录它在哪个环节更顺手 |

策略是“一主一备”：先把 Codex 和 WorkBuddy 用熟，再决定 Trae 是否成为你的备用员工。不要因为工具多，就把注意力花在切换工具上。

## 直播演示（35 分钟）

### 演示一：同一个任务挑员工（5 分钟）

给不同工具一个有明确输入和交付标准的小任务，不比较宣传口号，只比较：读材料、执行步骤、修错能力、返工次数和交付结果。

### 演示二：Codex（12 分钟）

选择以下任务之一：

1. 根据参考资料生成一张专业图片；
2. 打开网页，抓取指定信息并整理成表；
3. 读取一个项目，修改文件、运行检查并汇报结果。

涉及账号登录、发布、发送、删除或付费时，演示停在人工确认点。

### 演示三：WorkBuddy（10 分钟）

把一段真实但脱敏的材料交给 WorkBuddy，让它整理成表格、调研简报或 PPT 初稿，观察它的规划和办公交付能力。

### 演示四：Trae（5 分钟）

用 TraeCode 或 TraeWork 跑一件同类小任务，记录它在哪个步骤更顺手。Trae 的作用是让学员建立自己的判断，不是强行增加主线工具。

### 收尾（3 分钟）

每人选出一个主力员工和一个备用员工，填写入职卡；提醒大家：Codex 接入其他 AI 工具的具体方式放到 1.6。

## 学员练习

准备三件不含敏感信息的真实小任务：分别用 Codex、WorkBuddy、Trae 跑通一次，记录任务类型、输入材料、耗时、返工次数、最终结果和主观评分。

## 提示词模板

```text
我现在要完成的任务是：____。

请在 Codex、WorkBuddy、Trae 之间帮我做选择：
1. 先判断任务属于图片、浏览器自动化、跨文件执行、办公整理、外部调研还是代码开发；
2. 给出首选工具和备选工具，并说明理由；
3. 写出一个 10 分钟能完成的最小试用任务；
4. 列出输入、输出、检查标准和风险；
5. 涉及登录、发布、发送、删除或付费时，先停下来让我确认。
```

## 交付物

《AI 员工入职卡》：工具名 / 管什么 / 官方下载地址 / 跑通了什么 / 耗时 / 返工次数 / 还缺什么权限 / 我的评分。

《Codex / WorkBuddy 对比表》：任务场景 / 首选工具 / 实际结果 / 选择理由。

## 验收标准

- 能解释为什么优质 AI 工具会影响任务完成度；
- 能根据任务类型说出 Codex 和 WorkBuddy 的优先使用场景；
- WorkBuddy 和 Trae 至少各跑通一件最小任务，Codex 至少跑通图片、浏览器或跨文件任务中的一件；
- 能用真实试用记录而不是宣传口号做工具选择；
- 知道 Codex 接入其他 AI 工具属于 1.6 的升级内容。

## 常见误区

- 只看工具名气或安装难度，没看它能不能完整交付；
- 把个人实测经验说成所有人的绝对结论；
- 三个工具一次全装，却没有真实任务验证；
- 只比较回答质量，不比较调用工具、处理错误和交付结果；
- 把 Codex 接入其他工具和本课的基础入职混在一起，导致第一次配置过重。
